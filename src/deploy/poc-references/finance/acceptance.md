# 金融业·智能合规标杆 POC —— 验收标准

本文件是 POC 验收的「合同」：把 Killer Scenario 翻译成**可度量**的成功指标与**可执行**的验收步骤。
客户与交付方在 POC 启动会上签字确认 baseline，POC 结束时按本文件逐项核对 target。

---

## 1. 验收总览

| 指标 | Baseline | Target | 度量方式 | 责任人 |
|---|---|---|---|---|
| 研报成稿周期 | 3 工作日/篇 | ≤1 工作日/篇 | 系统时间戳（立项→成稿） | 研究所 |
| 合规条款比对覆盖率 | ≈40%（人工抽样） | 100% 逐条 | 比对任务统计 | 合规部 |
| 监管报送差错率 | 0.8% | ≤0.1% | 报送复核差错 | 合规部 |
| 合规人工复核工时/周 | 40 人时 | ≤12 人时 | 工时系统 | 合规部 |

---

## 2. 验收步骤（建议 2 周迭代）

### 第 1 周：铺包 + 制度接入
1. 用 `provision.py --poc finance --apply` 把骨架铺进客户租户（或 `--dry-run` 评审后执行）。
2. 把客户真实「监管法规摘要 / 内部合规制度」替换 `knowledge/seed/` 两份种子文档，重新灌库。
3. 报送连接器 `secret_ref` 配置为客户只读账号；`POST /api/mcp/servers/{id}/sync` 拉到 4 个工具。
4. 配置 `agent/playbook.yaml` 的 `model` 为客户实际部署的模型。

### 第 2 周：场景跑通 + 度量
5. 选取 **30 篇历史研报** 做合规比对盲测：记录命中红线条数、覆盖率、误报/漏报。
6. 选取 **1 个报送期** 做报送核对：记录缺失报表、字段差错、勾稽异常，与人工核对结果比对。
7. 记录研报成稿周期缩短比例、合规复核工时变化。
8. 与 baseline 比对，输出《POC 验收报告》。

---

## 3. 验收通过门槛（建议）
- 合规条款比对覆盖率 100%，红线漏报率 = 0。
- 报送核对发现的差错/缺失 ≥ 人工核对发现的（即不低于人工水平）。
- 研报成稿周期下降 ≥ 50%。
- 客户合规/研究负责人书面确认「可进入试点/采购评估」。

---

## 4. 风险与缓解
- **法规时效**：种子文档非现行有效 → 先以示意条款跑通，再接入客户受控制度与法规更新流。
- **数据敏感**：客户信息须脱敏 → 平台内容审核 + 最小化 + 审计留痕三道闸。
- **责任边界**：智能体只出结论/草稿，放行与报送由合规官确认 → 剧本已内置「不自动放行」约束。
- **模型幻觉**：收益/评级类表述须可回溯 → 技能内置「缺失口径须标注待核实」与红线预警。
